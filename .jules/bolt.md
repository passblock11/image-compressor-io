## 2025-08-08 - [Optimizing Image Compression via pyvips and Sync Endpoints]
**Learning:** For CPU-bound operations such as image processing, using FastAPI's asynchronous `async def` endpoints can block the single-threaded event loop, leading to poor concurrency under load. Utilizing synchronous `def` endpoints allows FastAPI to run tasks in its worker thread pool automatically. Furthermore, in pyvips (3.1.1), loading an image lazily using `new_from_buffer` and then applying `thumbnail_image` on it is ~30% faster than utilizing `thumbnail_buffer` directly, because it avoids recreating or re-reading buffers from scratch.
**Action:** Always prefer sync `def` endpoints for heavy CPU-bound tasks in FastAPI, and use `new_from_buffer` combined with `thumbnail_image` in pyvips for optimal speed and memory efficiency.
