## 2026-03-08 - Synchronous Route & Direct Stream Processing for Pillow
**Learning:** In FastAPI, CPU-bound endpoints (like Pillow image resizing and JPEG compression) defined with `async def` block the main event loop, causing server concurrency degradation. Defining them as regular `def` offloads work to Starlette's threadpool automatically. Furthermore, reading entire uploaded images via `await file.read()` causes unnecessary memory copies; opening directly from `file.file` and checking length with `seek`/`tell` preserves low memory footprint and enables Pillow's lazy reading.
**Action:** When handling CPU-bound image transformations with Pillow in FastAPI, always use synchronous `def` endpoints, validate size with `file.file.seek(0, io.SEEK_END)` and pass `file.file` directly to `Image.open`.
