## 2025-05-18 - Pillow Resampling and CPU-Bound FastAPI Optimization
**Learning:** For web image compression, `Image.LANCZOS` carries significant computational overhead compared to `Image.BICUBIC` (~33% slower downscaling) without perceptible quality benefits for standard downsampled web JPEGs. Furthermore, reading file streams via `file.read()` into `io.BytesIO` duplicates image memory buffers unnecessarily, whereas passing `file.file` directly to Pillow leverages lazy metadata decoding. Lastly, declaring CPU-bound image processing routes as `async def` in FastAPI blocks the asyncio event loop; switching to synchronous `def` allows Starlette to process them across worker threads.
**Action:** When handling image processing in FastAPI, pass file streams directly, use `Image.BICUBIC` for standard resizing downscales, return `getvalue()` directly from `io.BytesIO`, and declare endpoints as synchronous `def`.
