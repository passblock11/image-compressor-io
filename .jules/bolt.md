## 2025-05-15 - [pyvips migration and sync endpoint]
**Learning:** Migrating from Pillow to pyvips for image processing yielded a ~63% reduction in latency (from 0.2001s to 0.0740s) for the `/compress` endpoint. Using `pyvips.Image.thumbnail_buffer` enables "shrink-on-load" optimization, significantly reducing the memory and CPU required to process large images by only reading the necessary pixels for the target size. Additionally, converting the FastAPI endpoint from `async def` to `def` allows the CPU-bound task to be offloaded to a thread pool, preventing the event loop from being blocked and improving overall application responsiveness.
**Action:** Always consider `pyvips` for high-performance image processing tasks and prefer synchronous `def` for CPU-bound operations in FastAPI to leverage the built-in thread pool.
