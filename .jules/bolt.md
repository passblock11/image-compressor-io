## 2025-07-20 - [Migrated Image Compression from Pillow to pyvips and Async to Sync Def]
**Learning:** Pillow can be quite slow and resource-heavy when processing large images. By migrating the image processing engine to pyvips, using shrink-on-load via thumbnail_buffer, and saving JPEGs with optimized parameters (optimize_coding, strip, and interlace), we significantly reduced latency (by 16%-26%) and improved memory efficiency. Furthermore, switching the FastAPI endpoint from an `async def` to a synchronous `def` offloads CPU-bound compression work to FastAPI's internal thread pool, preventing the asyncio event loop from blocking and dramatically improving concurrency.
**Action:** Always prefer pyvips with shrink-on-load optimizations for CPU-heavy image compression workloads, and utilize FastAPI's built-in thread pool delegation for CPU-bound tasks by defining them as synchronous endpoints (`def` instead of `async def`).
