## 2025-02-18 - [FastAPI Thread Pools and pyvips Shrink-On-Load]
**Learning:** For heavy CPU-bound tasks such as image resizing and compression, defining the FastAPI endpoint as synchronous `def` instead of `async def` allows FastAPI to execute the handler in a background thread pool. This prevents blocking the main asyncio event loop, keeping the server responsive to other concurrent requests. Additionally, utilizing `pyvips` and `thumbnail_buffer` with shrink-on-load optimization results in a massive performance improvement (over 2.2x speedup / 55%+ latency reduction) compared to Pillow's Lanczos resize.
**Action:** Always prefer synchronous `def` for heavy CPU-bound image or data processing in FastAPI, and use `pyvips.Image.thumbnail_buffer` for high-performance, memory-efficient resizing.
